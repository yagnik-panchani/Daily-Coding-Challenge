# Day 58 - Queueable Apex Customer Lifetime Value Calculation

## 📌 Scenario

Build a Queueable Apex solution that automatically recalculates the **Customer Lifetime Value (CLV)** for an Account whenever an Opportunity is successfully closed.

Whenever an Opportunity is updated and its Stage changes to **Closed Won**, Salesforce should asynchronously calculate the total value of all Closed Won Opportunities related to that Account.

Instead of calculating the value directly inside the Trigger, the Trigger should enqueue a Queueable Apex job.

---

## 🚀 Business Requirements

When an Opportunity is updated:

- StageName changes to Closed Won

Then:

- Collect Account Ids
- Start a Queueable Apex job
- Query all Closed Won Opportunities
- Calculate total Opportunity Amount for each Account
- Update:

```
Customer_Lifetime_Value__c = SUM(Amount)
```

## 💡 Business Use Case

Many companies track the total revenue generated by each customer.

Instead of manually calculating the total value of every Closed Won Opportunity, Salesforce automatically recalculates the Customer Lifetime Value whenever a new Opportunity is successfully closed.

This information helps sales teams identify high-value customers and supports business reporting and customer segmentation.

## ⭐ Why Queueable Apex?

Queueable Apex performs the Customer Lifetime Value calculation asynchronously, preventing heavy calculations from slowing down the Trigger transaction.

This approach improves performance, follows Salesforce best practices, and supports processing multiple Accounts efficiently.

---

## 🎯 Interview Questions Practiced

### Why use Queueable Apex instead of calculating inside the Trigger?

Queueable Apex moves heavy calculations outside the Trigger transaction, making the application more scalable and reducing the risk of governor limit exceptions.

---

### Why use Aggregate SOQL?

Aggregate SOQL efficiently calculates summary values such as SUM, COUNT, AVG, MIN, and MAX directly in the database instead of processing every record manually.

---

### Why use AggregateResult?

AggregateResult stores the values returned by Aggregate SOQL queries, allowing Apex code to access calculated totals.

---

### Why use a Map?

A Map connects each Account Id with its calculated total, ensuring that every Account receives the correct Customer Lifetime Value.
